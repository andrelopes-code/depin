# Free-threading assumptions audit

This audit was run against CPython 3.13t and 3.14t with `Py_GIL_DISABLED=1`.
The runtime rules consulted are the [free-threading HOWTO](https://docs.python.org/3/howto/free-threading-python.html), [asyncio threading guidance](https://docs.python.org/3/library/asyncio-threading.html), [asyncio synchronization primitives](https://docs.python.org/3/library/asyncio-sync.html), and [Context Variables](https://docs.python.org/3/library/contextvars.html).

| Site | Shared state | Previous assumption | 3.13t / 3.14t finding | Disposition | Pinning test |
| --- | --- | --- | --- | --- | --- |
| `ScopeFrame._cache` | Cached singleton and scoped values | Dictionary check then insertion was effectively atomic | Both builds require the existing mutex around lookup/provide; reads and writes are protected | Retained mutex | `test_a_singleton_is_built_once_with_no_gil`, `test_scopes_stay_isolated_and_every_teardown_runs_with_no_gil` |
| `ScopeFrame._sync_locks` | Per-key `threading.Lock` table | A concurrent `get`/insert would hand out one lock | The table needs `_mutex` even with GIL disabled | Retained mutex | `test_the_per_key_lock_table_survives_concurrent_creation` |
| `ScopeFrame._async_flights` | Per-key completion events | An `asyncio.Lock` could be shared across loops | asyncio locks are not thread-safe or cross-loop primitives; both builds pass with mutex-protected events | Replaced with `threading.Event` flights | `test_async_singleton_is_single_flight_across_event_loops` |
| `ScopeFrame._teardowns` | LIFO teardown list | Appends/drains did not race | Mutation occurs only under `_mutex`; drains detach one immutable tuple | Retained mutex | `test_scopes_stay_isolated_and_every_teardown_runs_with_no_gil`, `test_sync_close_aggregates_failures` |
| Sync single-flight | Singleton construction across OS threads | GIL serialized miss/construct races | 3.13t and 3.14t require a per-key OS lock | Retained `threading.Lock` | `test_a_singleton_is_built_once_with_no_gil` |
| Async single-flight | Async singleton construction across OS threads and loops | A frame-owned asyncio lock was sufficient | Cross-loop waiters cannot share it; completion event wakes followers, which retry after failure/cancellation | Event flight with `asyncio.to_thread(event.wait)` | `test_async_singleton_is_single_flight_across_event_loops`, async failure/cancellation tests |
| `threading.Lock` and awaits | Frame mutex versus event loop | Holding an OS lock through await was harmless | It can block unrelated threads/loops; implementation releases `_mutex` before construction and `Event.set` | No OS lock is held across await | `test_async_singleton_is_single_flight_across_event_loops` |
| Scope `ContextVar` | Active frame in sibling tasks/threads | Context always follows a new thread | Tasks inherit context; threads depend on `thread_inherit_context`, so scopes are opened explicitly in each worker | Context-local API retained | `test_scopes_stay_isolated_and_every_teardown_runs_with_no_gil`, `tests/unit/test_scope.py` |
| Override `ContextVar` stack | Override inheritance/isolation | Overrides were process-global | Sibling task inheritance follows ContextVar semantics; sibling threads are isolated unless context is explicitly copied | Context-local stack retained | `tests/unit/test_overrides.py` |
| Graph/build structures | Dictionaries/lists while building a plan | Freeze structures might be concurrently mutated | They are call-local during freeze and not retained mutable after it returns | No shared state | `tests/unit/test_graph_properties.py` |
| `ResolutionPlan` | Post-freeze provider map/order | Readers needed a lock | Frozen plan data is immutable and only read after construction | Immutable reads retained | `tests/unit/test_container.py` |
| Missing-provider suggestions | `sys.modules` and module namespaces | Module dictionaries are stable while inspected | Snapshots are taken before searching; no shared depin mutation is retained | Snapshot reads retained | `tests/unit/test_errors.py` |
| FastAPI extension | Container `ContextVar` | Request container leaked across requests | ContextVar is request/task-local; integration opens an explicit async scope | Context-local integration retained | `tests/integration/test_fastapi.py` |
| Step 0 `gc.get_objects()` | Interpreter heap enumeration | GIL made heap walking a valid verification source | Removed before this step; free-threaded correctness is now demonstrated through public behavior | Historical only; no live code | `specs/evidence/2026-08-30-step-0-baseline.md` |

The cross-loop stress test uses 32 OS threads and one `asyncio.run` loop per thread. The one-loop tests additionally prove that a failed or cancelled leader removes and signals its exact flight, so a follower can construct rather than wait forever.
