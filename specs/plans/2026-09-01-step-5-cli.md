# Step 5, cycle 4 — the command and message hosts: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Click/Typer and Taskiq integrations on the cycle 1 contract, closing Step 5 — for the 0.16.0 milestone.

**Architecture:** One framework-free module, `depin/ext/cli.py`, declares the command seam structurally — anything with `with_resource` — and a generic `install` that opens a scope bound to that context's lifetime and returns the frame. `depin/ext/click.py` and `depin/ext/typer.py` are thin wrappers over it. `depin/ext/taskiq.py` is the only integration in the whole of Step 5 that must enter and exit a context manager by hand, and the `AsyncExitStack` doing so lives in a module-level `ContextVar` rather than on the middleware instance — the single correctness question in this cycle.

**Tech Stack:** Python 3.12–3.14, free-threaded CPython 3.13t/3.14t, pytest, pytest-asyncio, mutmut 3.7, mkdocs-material with mkdocstrings, uv. New optional dependencies: `click`, `typer`, `taskiq`.

**Spec:** `specs/2026-09-01-step-5-cli-design.md` — read it. Every design decision below is measured there, and the spec is binding over this plan.

## Global constraints

Every task inherits these from `AGENTS.md`, the roadmap, and the spec.

- The core keeps zero runtime dependencies. `click`, `typer` and `taskiq` appear only under `depin/ext/` and in `[project.optional-dependencies]`.
- **`depin/ext/cli.py` imports no third-party package**, not even under `TYPE_CHECKING`. This is an acceptance criterion. It is what lets a command framework outside the curated set use it, and it is what keeps `tests/unit/test_cli.py` runnable on the free-threaded and pre-release CI jobs.
- **No integration may import a third-party *private* name.** `typer._click` is out of bounds. depin forbids anyone reaching into its own private package and does not do it to someone else. This is why `depin.ext.typer.install` seeds nothing.
- Every integration module imports only from `depin`, `depin.errors`, `depin.ext.cli`, and its own framework, and **every name it takes out of `depin` must be in `depin.__all__`**. `tests/unit/test_integration_contract.py` enforces this and additionally forbids the literal substring `_core` anywhere in the file, **docstrings and comments included**. Write "depin's internals", never the name.
- Use PEP 695 syntax, including PEP 695 generics (`def install[C: CommandContext](...)`). No `TypeVar`.
- No `# type: ignore`, `# pyright: ignore`, `typing.cast`, `typing.Any`, or `# noqa`. `depin/` carries exactly three suppressions today — two in `depin/_core/frozen.py`, one in `depin/_core/markers.py` — and must carry exactly those three when this cycle ends. Confirm with `grep -rn "type: ignore\|pyright: ignore\|noqa" --include='*.py' depin`; the `# noqa: B008` inside a docstring in `depin/ext/fastapi.py` is prose, not a waiver.
- Public API carries Google-style docstrings that omit types from `Args:`/`Returns:`, list every exception under `Raises:`, and carry an `Example:`. A ```pycon fence is **executed as a doctest** by the default `pytest` run; an example needing a live CLI or broker must be an indented `::` literal block, as `depin/ext/asgi.py` does.
- Tests exercise the real `Container` / `FrozenContainer`. Do not mock the DI machinery.
- Tests are deterministic: no sleeps, no network, no clock dependence. The Taskiq concurrency test synchronises with `asyncio.Event`.
- **Coverage is measured with `uv run coverage run -m pytest` then `uv run coverage report`.** Never `pytest --cov`: depin's `pytest11` entry point imports `depin` before the collector starts and it under-reports (~73% against a true 99%). Coverage over `depin/` stays at or above 95%.
- Nothing under `depin/_core/` changes, so the mutation score is untouched — but the `mutation` workflow still runs, because its `paths:` filter includes `tests/**` and `pyproject.toml`. It is green on `main` at 97.7% and must stay green.
- Before every commit, in this exact order:

  ```bash
  uv run ruff format
  uv run ruff check
  uv run basedpyright
  uv run mypy
  uv run pytest
  ```

- Any commit that changes prose also runs `uv run --group docs mkdocs build --strict`.
- `uv run ruff format` reformats Python inside markdown fences, including under `specs/` and `docs/`. Never revert that.
- Commits are focused, conventional, at most 72 characters in the subject, and carry **no attribution, co-author trailer, or automation language**.

### Task 1: The command seam

**The hazard this task exists to close:** a non-generic `install`. With `install(ctx: CommandContext, *, seed: Callable[[CommandContext], ...])`, a caller passing `def seed_context(ctx: click.Context)` is rejected by both checkers — a callable parameter is contravariant, so `Callable[[click.Context], ...]` is not a `Callable[[CommandContext], ...]`. This is the same failure the ASGI triple hit in cycle 3, and the same answer: make it generic. Measured diagnostic, verbatim:

```
mypy: Argument "seed" to "install" has incompatible type "Callable[[Context], ...]";
      expected "Callable[[CommandContext], ...] | None"  [arg-type]
```

Getting this wrong is not caught by any test — only by Task 2's checkers, one task later, after the shape has hardened.

**Files:**

- Create: `depin/ext/cli.py`
- Create: `tests/unit/test_cli.py`

**Interfaces:**

- Produces: `depin.ext.cli.CommandContext`, `depin.ext.cli.install`.

- [ ] **Step 1: Write the failing tests**

Create `tests/unit/test_cli.py`, driving a **hand-written** object that satisfies `CommandContext` — an `ExitStack`-backed stand-in is the natural shape, since that is what a Click context does. Import no framework. One test each, named for what it pins:

- `install` returns the `ScopeFrame`, and a value seeded into it through the return value resolves inside the command.
- The container is published: `hosted_container()` returns the object `install` was given.
- The seed is applied before anything resolves, and the seeded key resolves to the seeded value.
- A `seed` returning `None` seeds nothing; omitting `seed` seeds nothing. Both still open the scope.
- **The scope drains when the context closes, not when `install` returns** — resolve a scoped provider with a teardown, assert the teardown has *not* run while the context is open, then close it and assert it has. This is the ordering the whole design rests on.
- After the context closes, `optional_hosted_container()` returns `None`.
- A body that raises still drains the scope and undoes the publication; the exception propagates.
- Two sequential commands get independent instances.

- [ ] **Step 2: Observe every new test fail**

```bash
uv run pytest tests/unit/test_cli.py -q
```

They must fail on the missing module, not on an assertion. Record the output.

- [ ] **Step 3: Write `depin/ext/cli.py`**

The module docstring says it needs no extra and imports no third-party package, and says why that matters — any command framework whose context can hold a resource works, not only the two shipped.

```python
class CommandContext(Protocol):
    """A command framework's context: anything that can own a resource for its own lifetime."""

    def with_resource[T](self, context_manager: AbstractContextManager[T], /) -> T: ...


def install[C: CommandContext](
    ctx: C,
    container: FrozenContainer,
    *,
    seed: Callable[[C], tuple[ProviderKey, object] | None] | None = None,
) -> ScopeFrame:
```

`install` calls `ctx.with_resource(Host(container).scope())`, applies the seed if it returned a pair, and **returns the frame**. Returning it is what lets the caller seed their own values — a tenant, a correlation id read off an option — before anything resolves; cycle 3's middlewares return nothing only because they have no caller.

`ScopeFrame` must be reachable from `depin`'s public surface for the return annotation. Check `depin.__all__` before writing the import; if it is not there, that is a finding to report, not something to work around with a private import.

### Task 2: Click and Typer

**The hazard this task exists to close:** seeding Typer's context. Measured on typer 0.27.2, the object handed to a callback annotated `typer.Context` is a `typer._click.core.Context`, and `isinstance(value, typer.Context)` is `False`. Seeding under the key `typer.Context` therefore binds a value that is not an instance of its own key — depin keys on the annotation, so it resolves and hands back a lie. Seeding under the private class instead makes depin depend on a third-party private name. **The module ships neither.** `depin.ext.typer.install` seeds nothing and says why in its docstring.

**Files:**

- Create: `depin/ext/click.py`, `depin/ext/typer.py`
- Create: `tests/integration/test_click_ext.py`, `tests/integration/test_typer_ext.py`
- Modify: `pyproject.toml`

- [ ] **Step 1: Declare the extras**

`click = ["click>=8.2"]` and `typer = ["typer>=0.15"]`. Use `uv add --optional` so `uv.lock` stays consistent, and commit the lockfile.

The Typer floor is deliberately **not** `>=0.26`, the release that vendored click. The protocol removes the vendoring problem — the same `install` was measured working on 0.15.4, 0.19.2, 0.25.1, 0.26.0 and 0.27.2 — so a floor at the split would invent a constraint the design does not have. Verify both floors resolve and pass with `uv sync --all-extras --resolution lowest-direct` before committing; CI's `minimum declared versions` job runs exactly that.

- [ ] **Step 2: Write the failing integration tests**

`tests/integration/test_click_ext.py` against `click.testing.CliRunner`, and `tests/integration/test_typer_ext.py` against Typer's runner. Import each framework **unguarded** at module level. Cover, for each:

- a scoped provider resolved inside a command;
- its teardown run, **after the command body returned**;
- two invocations getting independent instances;
- `hosted_container()` reachable from inside the command;
- a group with a subcommand (Click) — the scope spans the group callback, the subcommand and the result callback;
- a command that raises — the scope still drains;
- `--help` opens no scope.

For Click additionally: a provider reading something off the seeded `click.Context`, proving the seed is real.

For Typer additionally: a test that seeds the context **through the returned frame** under a key the user owns, which is the documented answer to the missing default seed.

- [ ] **Step 3: Write `depin/ext/click.py`**

A seed and a wrapper, in the shape of `depin/ext/flask.py`:

```python
def seed_context(ctx: Context) -> tuple[ProviderKey, object]:
    return Context, ctx
```

and an `install(ctx, container)` that calls `cli.install(ctx, container, seed=seed_context)` and returns the frame.

- [ ] **Step 4: Write `depin/ext/typer.py`**

`install(ctx, container)` calling `cli.install(ctx, container)` with no seed. The module docstring states the measurement — that `typer.Context` is not the runtime class since 0.26.0, that seeding under it would be false, and that reaching for `typer`'s private module is not something depin will do to another package — and tells the user to seed the context themselves through the returned frame under a key they own.

### Task 3: Taskiq

**The hazard this task exists to close, and the reason this task is separate:** a `TaskiqMiddleware` instance is shared across every message the worker handles. Holding the `AsyncExitStack` as an instance attribute was measured with three interleaved messages, and every `post_execute` received the **last** stack created — message C's — closing the wrong scope and leaking two others. Held in a module-level `ContextVar`, each `post_execute` received its own, because `pre_execute`, the task body and `post_execute` share one asyncio Task and therefore one Context.

**This is the only place in Step 5 where a context manager is entered and exited by hand, and it is the only correctness question in this cycle. The test that proves it must be shown to fail when the `ContextVar` becomes an instance attribute.** If deleting the fix keeps the suite green, the test proves nothing — `AGENTS.md` says so about concurrency guards, and this is one.

**Files:**

- Create: `depin/ext/taskiq.py`
- Create: `tests/integration/test_taskiq_ext.py`
- Modify: `pyproject.toml`

- [ ] **Step 1: Declare the extra**

`taskiq = ["taskiq>=0.11"]`. The middleware contract was measured identical on 0.11.0, 0.11.18 and 0.12.6. Verify the floor resolves and passes.

- [ ] **Step 2: Write the failing tests**

`tests/integration/test_taskiq_ext.py` against a real `InMemoryBroker`, importing `taskiq` unguarded. Cover:

- a scoped provider resolved inside a task;
- its teardown run when the task finishes;
- two messages getting independent instances;
- `hosted_container()` reachable from inside a task;
- the seeded `TaskiqMessage` readable by a provider;
- a task that raises — the scope still drains, and the error still surfaces;
- **the concurrency proof**: three messages interleaved with `asyncio.Event`, asserting each closed its own scope and no instance leaked between them.

Note `InMemoryBroker.startup()` overrides the base and **never calls middleware `startup`/`shutdown`** — do not write a test that depends on those firing.

- [ ] **Step 3: Write `depin/ext/taskiq.py`**

`MessageScope(TaskiqMiddleware)` holding the `Host`, with a **module-level** `ContextVar[AsyncExitStack | None]`. `pre_execute` enters `Host.ascope()` on a fresh stack, seeds the `TaskiqMessage`, and **returns the message it was given** — the receiver threads the return value onward, so returning `None` breaks execution. `post_execute` clears the var, then closes the stack.

The class docstring documents two hazards measured in the study:

- **Register it last.** A middleware registered after depin's that raises in its own `pre_execute` skips depin's `post_execute` and leaks the scope.
- `Host.activated()` **cannot** span `startup`/`shutdown`: they run in different tasks, so resetting the token raises `ValueError: Token was created in a different Context`. There is no process-wide publication story here.

- [ ] **Step 4: Prove the concurrency test bites**

Temporarily replace the `ContextVar` with an instance attribute, run the concurrency test, and **record the failure output**. Restore the `ContextVar` and confirm it passes. A guard that survives the removal of what it guards is not a guard. Put both outputs in your report.
