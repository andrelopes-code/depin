# Step 5, cycle 3 — the request/response hosts: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Starlette, Litestar and Flask integrations on the cycle 1 contract, extract the one ASGI middleware and the one WSGI middleware they and FastAPI all reduce to, and rewrite `depin.ext.fastapi` onto the extraction without editing a line of its two integration suites — for the 0.15.0 milestone.

**Architecture:** Two new protocol-only modules — `depin/ext/asgi.py` and `depin/ext/wsgi.py` — carry the whole behaviour: publish the container, open a scope, apply a caller-supplied seed, call downstream. Neither imports a third-party package; ASGI and WSGI are structural protocols and are declared locally with `typing.Protocol`. Three framework modules are then nothing but a `seed` callable and a re-export, and `depin.ext.fastapi.RequestScope` becomes `depin.ext.starlette.RequestScope`. The cost of a fourth framework after this cycle is one `seed` function.

**Tech Stack:** Python 3.12–3.14, free-threaded CPython 3.13t/3.14t, pytest, pytest-asyncio, Hypothesis, mutmut 3.7, mkdocs-material with mkdocstrings, uv. New optional dependencies: `starlette`, `litestar`, `flask`.

**Spec:** `specs/2026-08-31-step-5-web-design.md`

### Task 1: The ASGI middleware

**The hazard this task exists to close:** an ASGI middleware that opens a scope on every message type breaks the lifespan protocol. The lifespan scope is opened once, at startup, and lives for the whole process; wrapping it in a per-request scope leaks a frame for the application's lifetime and puts startup and shutdown inside a scope that never drains. The forwarding branch is therefore the first test written, and it is asserted by observing that no scope was opened, not merely that the call succeeded.

**Files:**

- Create: `depin/ext/asgi.py`
- Create: `tests/unit/test_asgi.py`

**Interfaces:**

- Produces: `depin.ext.asgi.RequestScope`, and the protocol types `ASGIApp`, `ASGIScope`, `Receive`, `Send`, `Message`.

- [ ] **Step 1: Write the failing ASGI tests**

Create `tests/unit/test_asgi.py`. Drive a hand-written downstream application — an `async def app(scope, receive, send)` that records what it saw — with **no framework installed and none imported**. One test each, each named for what it pins:

- A `lifespan` scope is forwarded untouched: the downstream app is called with the same three arguments, and `optional_hosted_container()` observed *inside* it returns `None`. Asserting `None` is what proves no scope was opened; asserting "it did not raise" proves nothing.
- An `http` scope publishes the container: `hosted_container()` inside the downstream app returns the same object the middleware was built with.
- An `http` scope applies the seed: a `Token` seeded by the `seed` callable resolves inside the downstream app to the seeded value.
- A `websocket` scope publishes the container but **does not** apply the seed: resolving the seeded token inside the downstream app raises, because nothing provided it.
- A `seed` that returns `None` seeds nothing, and the request still succeeds.
- No `seed` at all — the default — behaves the same as a seed returning `None`.
- A scoped provider's teardown runs when the request ends, exactly once, and a second request gets a fresh instance.
- An exception raised by the downstream app propagates, **and** the scope still drained: the teardown ran, and `optional_hosted_container()` after the call returns `None`.
- Two concurrent `http` requests, driven with `asyncio.gather`, each see their own seeded value. Synchronise with an `asyncio.Event` so the two are provably interleaved, never with a sleep.

Every assertion of a resolved value goes through the real `FrozenContainer`.

- [ ] **Step 2: Observe every new test fail**

```bash
uv run pytest tests/unit/test_asgi.py -q
```

They must fail on the missing module, not on an assertion.

- [ ] **Step 3: Write `depin/ext/asgi.py`**

The module docstring says it needs no extra and imports no third-party package, and says why that matters. The protocol types are declared locally:

```python
type Message = MutableMapping[str, object]
type ASGIScope = MutableMapping[str, object]


class Receive(Protocol):
    async def __call__(self) -> Message: ...


class Send(Protocol):
    async def __call__(self, message: Message, /) -> None: ...


class ASGIApp(Protocol):
    async def __call__(self, scope: ASGIScope, receive: Receive, send: Send, /) -> None: ...
```

`RequestScope` carries `__slots__ = ('_app', '_host', '_seed')`, and:

```python
    def __init__(
        self,
        app: ASGIApp,
        container: FrozenContainer,
        *,
        seed: Callable[[ASGIScope], tuple[ProviderKey, object] | None] | None = None,
    ) -> None:
```

`container` is keyword-or-positional because Starlette's `add_middleware(RequestScope, container=di)` passes it by keyword and `app` positionally. `seed` is keyword-only.

`__call__` reads:

```python
    async def __call__(self, scope: ASGIScope, receive: Receive, send: Send) -> None:
        if scope['type'] not in ('http', 'websocket'):
            await self._app(scope, receive, send)
            return
        async with self._host.ascope() as frame:
            if self._seed is not None and scope['type'] == 'http':
                seeded = self._seed(scope)
                if seeded is not None:
                    frame.provide(*seeded)
            await self._app(scope, receive, send)
```

The `http`-only condition on the seed is deliberate and documented: a websocket connection has no request body semantics, and the framework request classes that the seeds construct are HTTP-shaped.

### Task 2: The WSGI middleware

**The hazard this task exists to close:** WSGI hands the server an iterable that the server consumes *after* the application returns. A middleware that opens a `with` block around the call has already drained the scope by the time the first byte is produced. This is not fixable within WSGI — it gives no hook that outlives the return — so the task's job is to make the boundary explicit and to pin it with a test, rather than to leave a user to discover it in production.

**Files:**

- Create: `depin/ext/wsgi.py`
- Create: `tests/unit/test_wsgi.py`

**Interfaces:**

- Produces: `depin.ext.wsgi.RequestScope`, and the protocol types `WSGIApp`, `Environ`, `StartResponse`.

- [ ] **Step 1: Write the failing WSGI tests**

Create `tests/unit/test_wsgi.py`, against a hand-written `def app(environ, start_response)`, with no framework imported. One test each:

- The container is published: `hosted_container()` inside the downstream app returns the object the middleware was built with.
- The seed is applied before the downstream app runs.
- A `seed` returning `None`, and no `seed` at all, both seed nothing and still serve the request.
- The response bytes reach the caller unchanged.
- A scoped provider's teardown runs once per request; a second request gets a fresh instance.
- An exception from the downstream app propagates and the scope still drained.
- **The documented limitation, pinned as a test:** a downstream app returning a generator that resolves a scoped value *while being consumed* fails, and the failure is asserted for what it is. Name the test for the limitation it records. This is the test that stops a future refactor from silently changing the contract, and it is the one the guide's warning cites.

- [ ] **Step 2: Observe every new test fail**

```bash
uv run pytest tests/unit/test_wsgi.py -q
```

- [ ] **Step 3: Write `depin/ext/wsgi.py`**

Protocol types, declared locally, no third-party import:

```python
type Environ = MutableMapping[str, object]


class StartResponse(Protocol):
    def __call__(self, status: str, headers: list[tuple[str, str]], /) -> object: ...


class WSGIApp(Protocol):
    def __call__(self, environ: Environ, start_response: StartResponse, /) -> Iterable[bytes]: ...
```

`RequestScope.__call__` returns the downstream iterable from inside the `with`:

```python
    def __call__(self, environ: Environ, start_response: StartResponse) -> Iterable[bytes]:
        with self._host.scope() as frame:
            if self._seed is not None:
                seeded = self._seed(environ)
                if seeded is not None:
                    frame.provide(*seeded)
            return self._app(environ, start_response)
```

Do **not** wrap the return in `list()` to force materialisation. It would buy streaming safety at the price of buffering every response in memory, which is a worse default than the documented limitation, and it would break the one thing WSGI streaming is for. The class docstring states the boundary in the same words the guide uses.
